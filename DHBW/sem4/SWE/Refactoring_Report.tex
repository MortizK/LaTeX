\subsection{Umsetzung}

Im HomeController habe ich zwei Funktionen: \lstinline|private void loadXMLTabContent()| und \lstinline|private void loadPDFTabContent()|, die ähnlich klingen und ähnlich sind. Hier kann ich \href{https://refactoring.com/catalog/parameterizeFunction.html}{Parameterize Function} verwenden, um zwei Funktionen in eine Funktion mit geeigneten Parametern zu ändern.

Im Tasks Model habe ich zwei Funktionen, die dasselbe String-Formatting durchführen. Hier kann ich \href{https://refactoring.com/catalog/extractFunction.html}{Extract Function} verwenden, um \lstinline|toTitleCase| zu erstellen.

\begin{lstlisting}[style=javastyle]
public String getFormatedDifficulty() {
    String diff = difficulty.toString();
    return toTitleCase(diff);
}
public String getFormatedScope() {
    String sc = scope.toString();
    return toTitleCase(sc);
}
private String toTitleCase(String s) {
    return s.charAt(0) + s.substring(1).toLowerCase();
}
\end{lstlisting}

Mein DataService vermischt derzeit das Aktualisieren der Benutzeroberfläche und die Zustandsverwaltung. Dies könnte mit \href{https://refactoring.com/catalog/extractClass.html}{Extract Class} umgestaltet werden. Dies könnte zu zwei möglichen Klassen führen: ExamNavigationService und ViewStateService.

Insgesamt habe ich mehrere weitere Stellen gefunden, an denen eine Umgestaltung sinnvoll wäre, und ich bin nicht zufrieden mit der Codequalität. Ich werde eine Refactoring-Planung durchführen, um zu sehen, ob es sich lohnt, einige oder das Gros meiner Anwendung neu zu schreiben (entweder nur als Lernerfahrung oder um den Code dort zu verbessern, wo nötig).
